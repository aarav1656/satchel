## Fixes made

No defect in the live site or the SDK was found, so apps/web app code and packages/sdk are unchanged and nothing was redeployed. Harness changes only, in apps/web/scripts:
- drive.mjs: `tclick` also finds links; new `tclick_sel` (real click at a selector) and `type_into` (real click, select, Input.insertText), so the click-through uses real input for every click instead of element.click().
- steps-click-through.mjs: a second memory is sealed before the grant (item 2), a third after the revoke, row counts and open,open,locked assertions follow; an assertion that the unfunded error is not REGISTRY_UNREACHABLE; the second-origin Fern step runs only when the origin has the local alias; the /proof block starts from a fresh load with a navigator.credentials counter and asserts exactly one get and zero create.
- click-through.sh: LABEL and DRIVE_LOG env, skips the local static server for a remote ORIGIN, so a live run does not overwrite the local run's results.
- steps-prompt-counter-control.mjs: the counter's negative control (one vault click reads 1, one extra get moves it to 2).

## Blind spots

- The virtual authenticator is software: it proves the flows and PRF handling in Chrome 154 under CDP, not a platform authenticator on a phone or a hardware key.
- The scan's one `not satchel's` row on live is a sessionStorage key from the Phantom extension in the QA profile (`phantom.contentScript.providerInjectionOptions.v3`), correctly not flagged.
- The REGISTRY_UNREACHABLE negative assert was not mutation-tested live (it would need the page to misreport); the unfunded path itself has mutation runs in results/sdk-new-mutations.txt.
- check-built read the local out/ directory that the live HTML and chunks match byte for byte, not a download of the live site into the check's directory.
- Mobile checks are Emulation metrics with DOM reads, not a physical device or a touch-input pass.
