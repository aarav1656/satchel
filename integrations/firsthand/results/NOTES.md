Working notes, 2026-10-02. Re-run 2026-10-03 against upstream main a3a078c; both patches applied unchanged.

- Where Firsthand derives: packages/crypto/src/kdf/{info,keytree,scalar}.ts and packages/crypto/src/prf/PrfSource.ts, ceremony in packages/sdk/src/webauthn/WebAuthnPrfSource.ts, called from Locker.open, FirsthandClient and apps/capture/src/lib/prf.ts. PRF eval salt sha256("FIRSTHAND/prf/v1"); PRK = HKDF-Extract(salt "FIRSTHAND/kdf/v1", prf); k_id = Expand(info "id" 0x00, 48) reduced mod (n-1) plus 1 on P-256; k_ns,e = Expand(info "ns" 0x00 u32be(ns) u64be(e), 32); k_dep = Expand("dep" ..., 48) on secp256k1; k_nonce = Expand("nonce" ..., 32). Epochs are time based (epochAt), not registry based.
- Shape chosen: adapter. Reasons: the principal id and every deposit origin on chain are functions of these keys, so replacing the module changes them for every holder. Firsthand also already has one tap per unlock, so satchel's one-prompt session is not a gain for the locker; the measured cost of using satchel beside it the plain way is a second tap (different PRF salt), and the adapter removes it.
- satchel root is an HKDF branch of the PRF output, not the PRF output. Reason: Satchel.addPasskey() wraps the satchel root under a second passkey and stores it; had the root been the raw PRF output, that wrap would have been a backup of the whole locker tree. Not run: addPasskey itself (needs a second ceremony and a store in the harness).

The PR text points at the satchel repo, not npm.
